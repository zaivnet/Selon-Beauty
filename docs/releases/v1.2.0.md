## Overview

Version 1.2.0 delivers three major operational enhancements to the platform:

1. **Feature #1: Dashboard Status Operasional Hari Ini — “Semua Outlet”**
   - High-level multi-outlet operational monitoring for Superadmin and Owner roles.
   - Preserves scoped Admin outlet isolation via `OutletScopeService`.
   - Maintains WORK Outlet semantics for operational headcount and active shift tracking.
   - Correctly attributes temporary cross-outlet assignments.

2. **Feature #2: Reactive Attendance Report Filters**
   - Fast, buttonless reactive filtering on the administrative attendance report.
   - Dynamic cascading between Outlet selection and Employee dropdown options.
   - Dynamic employee list recalculation on date range adjustments.
   - Shared filter query builder providing 100% parity across Web, Print preview, and CSV export.
   - Security verification preventing unauthorized outlet query tampering (`403 Forbidden`).

3. **Feature #3: Automatic Shift Checkout**
   - Per-shift configurable Auto Checkout toggle and grace minutes.
   - Immutable check-in snapshots (`scheduled_shift_end_at`, `break_minutes_snapshot`, `auto_checkout_boundary`).
   - Automated background scheduler (`attendance:auto-checkout`) processing due boundaries every minute.
   - Explicit `checkout_source` provenance (`manual` vs `auto_shift_end`).
   - Seamless cross-midnight shift support.
   - Automatic dispatch of in-app notifications upon auto-checkout.
   - Full protection of legacy data: historical attendance records without snapshots are never auto-closed.

## Special Upgrade Notes

- Existing shifts migrate with Auto Checkout **OFF** (`auto_checkout_enabled = false`).
- Administrators must explicitly enable Auto Checkout on existing shifts if desired.
- Newly created shifts default to Auto Checkout **ON** with a 10-minute grace period.
- Historical attendance records remain untouched with `auto_checkout_boundary = NULL` and are not auto-closed.
- Auto checkout applies strictly to check-ins created with immutable boundary and metric snapshots.
- Run `php artisan migrate --force` to apply the additive database schema changes.
- Ensure the existing scheduler cron (`* * * * * php /path/to/artisan schedule:run`) remains active.

## Upgrade Instructions (Existing v1.1.0 Installation)

Follow this standardized procedure when upgrading from v1.1.0 to v1.2.0:

1. **Preserve Environment & Configuration**: Ensure `.env` and `APP_KEY` remain unchanged.
2. **Preserve Production Database**: The existing database must remain untouched with zero data resets.
3. **Preserve Private Media**: Private selfie evidence, leave attachments, and branding files must remain in storage.
4. **Create Pre-Upgrade Safety Backup (MANDATORY)**:
   - Command `app:run-scheduled-backup` is schedule-aware. To execute immediately from CLI, pass `--force`:
     ```bash
     /home/<user>/bin/php84-attendance artisan app:run-scheduled-backup --force
     ```
   - Alternatively, trigger a manual Full Backup from Admin UI: **Pengaturan $\rightarrow$ Backup & Pemulihan** (`/admin/settings/backups`) $\rightarrow$ **"Buat Backup Sekarang"**.
   - **Backup Format & Integrity Validation Note**:
     - Backup archives in `storage/app/private/backups/` use `.zip` extension but are packaged as JSON containers with base64-encoded files (`backup-manifest.json`, `database/dump.json`, `checksums.json`, private media).
     - **DO NOT** use `unzip -t` for validation.
     - Validate that physical file size $> 0$ bytes, SHA-256 hash matches `backup_records.checksum`, and container decodes valid JSON/manifest/dump data.
5. **Deploy Immutable v1.2.0 Release Code**:
   ```bash
   git fetch --tags --prune
   git checkout v1.2.0
   ```
6. **Apply Additive Database Migrations**:
   ```bash
   /home/<user>/bin/php84-attendance artisan migrate --force
   ```
7. **Rebuild Application Caches**:
   ```bash
   /home/<user>/bin/php84-attendance artisan optimize:clear
   /home/<user>/bin/php84-attendance artisan config:cache
   /home/<user>/bin/php84-attendance artisan route:cache
   /home/<user>/bin/php84-attendance artisan view:cache
   ```
8. **Verify Scheduler Registration**:
   ```bash
   /home/<user>/bin/php84-attendance artisan schedule:list
   ```
   *(Expected: `attendance:auto-checkout` registered every minute alongside `app-run-scheduled-backup`)*
9. **Perform Post-Upgrade Verification**:
   - Verify administrative login and Dashboard "Semua Outlet" view.
   - Verify Attendance Report reactive filtering and export functionality.
   - Verify Shift Management (confirm existing shifts show Auto Checkout OFF).
   - Selectively enable Auto Checkout on desired operational shifts.

## Rollback Protocol

If a rollback to v1.1.0 code is required:
- The database schema additions in v1.2.0 (`auto_checkout_enabled`, `auto_checkout_grace_minutes`, `checkout_source`, `auto_checkout_boundary`, `scheduled_shift_end_at`, `break_minutes_snapshot`) are nullable or defaulted.
- Application code at v1.1.0 safely ignores these extra columns without requiring a database rollback.
- Roll back application code (`git checkout v1.1.0`), refresh caches (`optimize:clear`, `config:cache`, `route:cache`, `view:cache`), and investigate error logs.
